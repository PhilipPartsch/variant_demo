## 1. Decisions and reviews

### M-01 Review and merge the content (plan 4)

- **What:** branch `content/cv-platform` (14 commits, pushed): user stories,
  requirements, architecture, BMS black boxes, swreqs, C code and tests, risks,
  decisions, reports, imported evidence, review verdicts.
- **How:** read [04-content-result.md](04-content-result.md) §1–§3, then the
  pages per product (`tools/build_all.sh`, open `build/site/<product>/sphinx/index.html`)
  or the diff `git diff main...content/cv-platform -- docs src tests`.
- **Result:** OK → the agent merges into `main` (rebase on `main` first; the
  marker `content/cv-platform@25b77bd` in plan 99 stays valid as long as the branch exists).

### M-02 Open review points of plan 4

- **What:** the scores of 1 listed in [04-content-result.md](04-content-result.md) §6
  (charging current limit, interface derating, power-limit ownership VCU / ENG,
  ENG units, range estimate, BMS open points, decision rationale).
- **Choice:** apply now (one more authoring + review round) / later / never.

### M-03 Approve the golden files (plan 5)

- **What:** `tools/tests/golden/<product>.needs.json` and `<product>.variants.json`,
  the oracle of DOC-11; generated by the agent from the reviewed content.
- **How:** look at the summary the agent provides (needs per type and product,
  the values of C§8.1, the diff between products); accept or name the deviation.
- **Rule:** later changes to golden files only through a reviewed commit (T§2).

### M-04 CNT-05 as `xfail` (plan 5)

- **What:** CNT-05 requires a fresh verdict for every authored need in every
  product. Alternatives with one id cannot have that (plan 99 PH-01; today 8
  outdated in N / B, 2 in A, 0 in D).
- **Choice:** `xfail` with reason "PH-01" (proposal, as T§10 requires for tool
  bugs) / exclude the alternative ids explicitly / drop CNT-05.

### M-06 Windows in L9 (plan 5)

- **What:** L9 runs L1–L3 on Linux (CI) and macOS (local); Windows is optional.
- **Choice:** leave Windows out (proposal) / add a Windows job (needs another ubc install route, plan 99 UA-01).

### M-10 `choose` migration (plan 4)

- **When:** a sphinx-needs release with `choose` exists and ubc supports it.
- **Choice:** migrate showcases A / B (and the market alternative) from
  complementary `if` blocks to `choose`; the per-product `needs.json` must stay
  unchanged (agent checks).

### M-11 Demo dry run (plan 4)

- **What:** the walk-through of C§8.1 — switch the four products in the CMake
  Tools status bar and show showcase A / B, BMS values and code needs.
- **Result:** note what did not show as expected (feeds M-05 deviations).

### M-12 Plan 99 to useblocks

- **What:** [99-tool-bugs.md](99-tool-bugs.md) — which entries go to which team
  (ubc / ubCode, Pharaoh, Sphinx-Needs, Sphinx-Codelinks, sphinx-mounts), and how
  (issues on GitHub for the open-source tools, internal channel for the others).
- **Result:** per entry: reported (link) / not reported.

### M-13 Open points for the BMS team

- **What:** no BMS interface requirement for a permitted charging power
  (`BB_CHARGE_LIMITS`) or for the isolation-fault reaction time
  (`BB_HV_PROTECTION`); interface tags and per-chemistry release artifacts are
  still done on the CV side (`tools/pin_bms.py`, B§5.2).
- **Choice:** raise with the BMS repository now / later.
